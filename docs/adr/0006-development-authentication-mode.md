# ADR 0006: Development-only authentication mode

| Status | Date |
|---|---|
| Accepted | 2026-10-24 |

## Context
Running the app locally shouldn't require an Entra tenant, and testing multi-user scenarios (owner, viewer, admin) with real accounts is slow. But a fake sign-in that leaks into a deployed environment would be a critical vulnerability.

## Decision
`Authentication:Mode = Development` makes the web app sign users in by display name. It then mints short-lived (10-minute) JWTs signed with a **random key generated by the AppHost on every run**, and the API validates them. It's guarded by:
1. Both apps **refuse to start** if the mode is set outside the `Development` environment.
2. Both apps refuse to start without the signing key, which only the AppHost provides.
3. The API logs a warning at startup when the mode is on.
4. The default mode in `appsettings.json` is `EntraExternalId`. Development mode is set only in the AppHost's `appsettings.Development.json`.

Authorization (scope, roles, family permissions) is identical in both modes. Only token issuance differs.

## Consequences
- `dotnet run --project src/Harmonee.AppHost` works on a fresh clone, and multi-user flows are quick to test.
- There's extra code to maintain. Keep it isolated (`Harmonee.Web/Authentication/DevelopmentSignIn.cs`, `DevelopmentAccessTokenProvider`, `Harmonee.Api/ApiAuthentication.cs`).
